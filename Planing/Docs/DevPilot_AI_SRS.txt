============================================================
1. PROJECT OVERVIEW
============================================================

DevPilot AI is a web-based platform designed exclusively for software developers.

The platform helps developers solve real-world programming problems through AI-powered debugging. The system analyzes the developer's problem, error, code, logs, or screenshots, explains the root cause, and provides a step-by-step solution.

After every solution attempt, the developer can select:

1. Solved
2. Still Have a Problem

If the problem is not solved, the AI performs another debugging attempt using the new information and provides another solution. This loop continues until the developer confirms that the problem is solved.

When a problem is solved, the system stores the complete problem and solution history in the database and uses the information to generate an educational article.

The platform also builds a public developer knowledge base similar in concept to Stack Overflow, where developers can search and read previously solved problems.

The system continuously improves its knowledge by collecting successful solutions from different developers, identifying similar problems, and synthesizing better solutions and updated educational articles.

DevPilot AI also integrates with GitHub to support repository debugging, AI code review, challenge repository creation, and practical developer training.

============================================================
2. PROJECT OBJECTIVES
============================================================

The main objectives are:

- Help developers solve programming problems faster.
- Provide understandable explanations instead of only giving final answers.
- Guide developers through debugging step by step.
- Reuse previously successful solutions.
- Reduce unnecessary LLM API requests and token consumption.
- Build a continuously improving developer knowledge base.
- Convert solved real-world problems into educational articles.
- Allow developers to practice problems through practical coding challenges.
- Integrate GitHub into the debugging and learning workflow.
- Provide AI-powered code review.
- Provide a Telegram interface for searching existing solutions.
- Support multiple free LLM providers with automatic failover.
- Build a scalable architecture while respecting free hosting and API limitations.

============================================================
5.2 AI DEBUGGING WORKSPACE
============================================================

The system shall provide a dedicated workspace for submitting technical problems.

A developer may provide:

- Problem description.
- Error message.
- Exception.
- Stack trace.
- Source code.
- Logs.
- Screenshots.
- Relevant technical information.
- Technology/framework information.

The system shall create a Problem record for each new debugging session.

The AI shall:

- Analyze the submitted information.
- Identify possible causes.
- Determine the probable root cause.
- Explain the problem.
- Provide a step-by-step solution.
- Explain why each step is required.
- Provide code examples when appropriate.
- Avoid presenting unsupported assumptions as confirmed facts.

The solution shall be stored as a debugging attempt.

============================================================
5.3 SOLUTION FEEDBACK LOOP
============================================================

After each AI solution, the system shall ask the developer:

"Did this solve your problem?"

Available options:

- Solved
- Still Have a Problem

If the developer selects "Solved":

- Mark the problem as solved.
- Store the successful solution.
- Store the complete debugging history.
- Generate or update the related educational article.
- Update problem statistics.
- Make the successful knowledge available for future similarity searches.

If the developer selects "Still Have a Problem":

- Request additional information when necessary.
- Store the developer's feedback.
- Start another debugging attempt.
- Provide a new or modified solution.
- Repeat the feedback cycle.

============================================================
5.9 TOKEN OPTIMIZATION
============================================================

The platform shall minimize unnecessary LLM usage.

If a highly similar solved problem exists:

- Retrieve the previous request.
- Retrieve the successful solution.
- Provide the previous knowledge as context to the LLM.
- Ask the LLM to adapt the existing solution to the current case.

The system shall not blindly reuse an old solution without validation/adaptation.

Every new successful adaptation shall be stored.

This creates a growing repository of proven solutions.

============================================================
5.10 SOLUTION EVOLUTION
============================================================

When multiple developers solve similar problems using different successful solutions, the system shall be able to collect the successful solution variants.

Example:

Request A -> Solution A -> Success
Request B -> Solution B -> Success
Request C -> Solution C -> Success

The AI may synthesize these successful solutions into an improved solution.

The improved solution can be used to update the related knowledge article.

The system should preserve historical versions of the article/solution.

The knowledge base is therefore intended to be continuously improving.

5.24 FREE LLM PROVIDER FAILOVER
============================================================

The platform shall support multiple free or free-tier LLM providers.

The system shall maintain provider information such as:

- Provider.
- Model.
- Priority.
- Status.
- Requests used.
- Token usage when available.
- Rate limits when known.
- Last error.
- Cooldown period.
- Availability.

When a provider reaches a rate limit or becomes unavailable:

1. Detect failure.
2. Mark provider temporarily unavailable.
3. Select another available provider.
4. Retry according to configured policy.
5. Return the result to the user without exposing internal provider switching.

Provider limits shall be treated as dynamic configuration and should not be hard-coded as permanent values.

12. AI PROCESSING PIPELINE
============================================================

The recommended AI processing pipeline is:

1. Receive user request.
2. Validate request.
3. Normalize technical information.
4. Extract technology/error indicators.
5. Search similar problems.
6. Evaluate similarity confidence.
7. If suitable knowledge exists, retrieve successful solutions.
8. Build optimized AI context.
9. Send request to AI Gateway.
10. Select available provider/model.
11. Receive AI response.
12. Validate/normalize response.
13. Store request and response.
14. Present solution to developer.
15. Wait for developer feedback.
16. If solved, finalize knowledge.
17. If not solved, continue debugging.
