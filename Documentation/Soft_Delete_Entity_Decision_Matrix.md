# Soft Delete Entity Decision Matrix

| Entity | Table | Category | Soft Delete? | Existing Lifecycle | Reason | Notes |
|---|---|---|---|---|---|---|
| **User** | `Users` | A. Soft Deletable | **Yes** | `EmailVerifiedAt`, `CreatedAt` | Represents primary developer identity and tenant account. Users may delete their account via `DELETE /api/users/me`. Physical deletion must never occur in order to preserve audit trails, problem tickets, code reviews, and challenge records. | Implements `ISoftDeletable` (`IsDeleted`, `DeletedAt`). Excluded by global query filter. Tokens revoked upon deletion. |
| **Problem** | `Problems` | A. Soft Deletable | **Yes** | `Status` (`ProblemStatus`), `ResolvedAt`, `CreatedAt` | Developers own their submitted problems and may remove them from their active workspace. However, the debugging telemetry, solutions, and AI prompts must remain preserved for learning and analytics. | Implements `ISoftDeletable`. Filtered from normal queries and searches. Children preserved. |
| **ProblemRequest** | `ProblemRequests` | C. Append-Only / Historical | **No** | `CreatedAt` | Represents an immutable snapshot of developer code, logs, and stack trace that triggered debugging. Part of the append-only debugging history. | Retained under parent `Problem`. Never deleted independently. |
| **ProblemAttachment** | `ProblemAttachments` | A. Soft Deletable | **Yes** | `UploadedAt` | User-uploaded logs, code dumps, or screenshots. Users can logically delete attachments from their requests, but the metadata and storage reference must remain for auditability. | Implements `ISoftDeletable`. Excluded from normal attachment queries. |
| **DebuggingAttempt** | `DebuggingAttempts` | C. Append-Only / Historical | **No** | `AttemptNumber`, `CreatedAt` | Immutable AI-generated debugging iterations containing root cause analysis and proposed fixes. Must be permanently retained for telemetry and model evaluation. | Never deleted. Form permanent AI telemetry history. |
| **DeveloperFeedback** | `DeveloperFeedbacks` | C. Append-Only / Historical | **No** | `FeedbackResult`, `CreatedAt` | Immutable user feedback on debugging attempts (Success/Failure/Partial). Permanent telemetry for AI accuracy benchmarks. | Append-only feedback log. Never deleted. |
| **ProblemSolution** | `ProblemSolutions` | A. Soft Deletable | **Yes** | `SolvedAt` | Curated/verified solutions to problems. May be retired or deleted if obsolete, while preserving past solution history for similarity matching and analytics. | Implements `ISoftDeletable`. Filtered from active solution recommendations. |
| **KnowledgeArticle** | `KnowledgeArticles` | A. Soft Deletable | **Yes** | `IsPublished`, `CurrentVersion`, `CreatedAt` | Documentation generated from solved problems. Can be deleted/unpublished from public knowledge base, but versions, view counts, and references remain in database. | Implements `ISoftDeletable`. Hidden from public article queries and search. |
| **ArticleVersion** | `ArticleVersions` | C. Append-Only / Historical | **No** | `VersionNumber`, `CreatedAt` | Immutable historical revisions of an article. Explicitly retained to guarantee full auditability and article revision history. | Retained permanently under `KnowledgeArticle`. |
| **Challenge** | `Challenges` | A. Soft Deletable | **Yes** | `Difficulty`, `CreatedAt` | Coding practice challenges. Can be retired or removed from the catalog by instructors/admins, but historical user attempts must remain intact. | Implements `ISoftDeletable`. Excluded from catalog listings. |
| **ChallengeAttempt** | `ChallengeAttempts` | C. Append-Only / Historical | **No** | `Status`, `StartedAt`, `SubmittedAt` | Developer exercise submissions. Represents user progress, metrics, and learning history that should never be deleted. | Managed by lifecycle state (`InProgress`, `Submitted`, `Evaluated`). |
| **ChallengeEvaluation** | `ChallengeEvaluations` | C. Append-Only / Historical | **No** | `EvaluatedAt` | Automated score report and code quality assessment. Immutable evaluation audit record. | 1-to-1 relationship with `ChallengeAttempt`. Never deleted. |
| **GitHubAccount** | `GitHubAccounts` | B. Lifecycle/Status Based | **No** | `ConnectedAt` | External OAuth connection. Disconnecting a GitHub account is managed via OAuth credential invalidation and connection lifecycle, not logical record deletion. | Tokens cleared/revoked on disconnect. History preserved. |
| **GitHubRepository** | `GitHubRepositories` | A. Soft Deletable | **Yes** | `IsPrivate` | Imported repositories in developer workspace. A developer may unlink/remove a repo from their workspace, but historical code reviews on it must remain valid. | Implements `ISoftDeletable`. Hidden from active repository lists. |
| **CodeReview** | `CodeReviews` | A. Soft Deletable | **Yes** | `ReviewedAt` | Code review runs executed on a repository/branch. Developers may delete a review from their dashboard while preserving historical findings for audit. | Implements `ISoftDeletable`. Filtered from normal review queries. |
| **CodeReviewFinding** | `CodeReviewFindings` | C. Append-Only / Historical | **No** | `Severity` | Detailed lint/security issues identified within a code review. Immutable child findings belonging to the review session. | Child history preserved under `CodeReview`. |
| **AIProvider** | `AIProviders` | B. Lifecycle/Status Based | **No** | `Status` (`ProviderStatus`), `RateLimitedUntil` | Infrastructure configuration for LLM providers (Groq, Gemini, OpenRouter, etc.). Managed via lifecycle states (`Active`, `Inactive`, `RateLimited`, `Degraded`). | Operational configuration; deletion is inappropriate. |
| **AIModel** | `AIModels` | B. Lifecycle/Status Based | **No** | `IsActive`, `CreatedAt` | Provider model configurations. Activated or deactivated via `IsActive` flag. | Managed via operational activation lifecycle. |
| **AIRequest** | `AIRequests` | C. Append-Only / Historical | **No** | `CreatedAt`, `DurationMs`, `Success` | Permanent ledger of token usage, latency, provider selection, and API cost tracking. Append-only system audit log. | Must never be deleted under any circumstances. |
| **Role** | `Roles` | D. System / Reference Data | **No** | Static Reference | System authorization definitions (`Developer`, `Administrator`). Essential application reference metadata. | Modifying or deleting core roles breaks system security. |
| **UserRole** | `UserRoles` | F. Join / Relationship Data | **No** | Composite Primary Key | Relational link between users and assigned roles. Role unassignment directly removes the junction link without needing soft-delete overhead. | Standard junction entity. Cascade delete prohibited (`NoAction`). |
| **RefreshToken** | `RefreshTokens` | E. Security / Session Data | **No** | `IsRevoked`, `RevokedAt`, `IsUsed`, `ExpiresAt` | Cryptographic session tokens. Lifecycle is fully governed by revocation, single-use rotation, and expiration timestamps. | Adding `IsDeleted` would be redundant and dangerous. Tokens revoked upon user soft-deletion. |
| **EmailVerification** | `EmailVerifications` | E. Security / Session Data | **No** | `VerifiedAt`, `ExpiresAt`, `Attempts` | Single-use verification codes/tokens. Lifetime governed by expiration window (15/30 min) and consumption timestamp (`VerifiedAt`). | Transient security data with natural expiration lifecycle. |

## Planned / Candidate Supporting Entities (Future Phases)

| Entity | Planned Table | Category | Soft Delete? | Existing Lifecycle | Reason | Notes |
|---|---|---|---|---|---|---|
| **AuditLogs** | `AuditLogs` | C. Append-Only / Historical | **No** | `Timestamp` | Security compliance and operational audit log. By definition append-only and immutable. | Must never support deletion (hard or soft). |
| **ProblemEmbeddings** | `ProblemEmbeddings` | C. Derivative Technical Data | **No** | `GeneratedAt` | Vector representations generated from problem text. Overwritten or regenerated when problem changes. | Technical derivative data. |
| **SimilarityMatches** | `SimilarityMatches` | C. Derivative Technical Data | **No** | `MatchedAt` | Ephemeral or cached similarity calculation results. | Technical cache/analytics data. |
| **Technologies** | `Technologies` | D. System / Reference Data | **No** | Static / Master Data | Master taxonomy of supported frameworks (e.g., C#, Python, React). System catalog data. | Maintained by administrators. |
| **ProblemTechnologies** | `ProblemTechnologies` | F. Join / Relationship Data | **No** | Composite Key | Many-to-many junction table between problems and technologies. | Standard junction link. |
| **Notifications** | `Notifications` | B. Lifecycle/Status Based | **No** | `IsRead`, `ReadAt` | User notifications. Managed by read/dismiss lifecycle. | Historical notification log. |
| **DiscordUsers** / **TelegramUsers** | Integrations | B. Lifecycle/Status Based | **No** | `IsActive`, `LinkedAt` | External bot user bindings. Managed by connection lifecycle. | Connection status. |
| **DiscordEvents** / **TelegramMessages** | Integrations | C. Append-Only / Historical | **No** | `CreatedAt` | External webhook event payloads. Append-only logs. | Event telemetry. |
